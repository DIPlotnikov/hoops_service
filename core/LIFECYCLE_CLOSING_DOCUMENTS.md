# LIFECYCLE_CLOSING_DOCUMENTS.md

## Жизненный цикл закрывающих документов

Документ описывает полный жизненный цикл закрывающих документов в системе Hoops, включая роли, статусы, этапы, возможные действия и используемые объекты.

---

### Основные сущности

- **ClosingDocument** — основной объект закрывающего документа, связывает администратора, задачи, файлы, даты периода, статусы и флаги.
- **ClosingDocumentFile** — отдельный файл закрывающего документа (например, счёт-фактура, акт).

---

### Роли участников

- **Администратор** — создает, архивирует, активирует, отправляет, помечает как оплаченные, блокирует периоды.
- **Менеджер** — просматривает отправленные закрывающие документы, связанные с его гостиницей.

---

### Этапы жизненного цикла

1. **Создание**
   - Инициируется администратором через GraphQL-мутацию `CreateClosingDocument`.
   - Передаются параметры: id гостиницы, даты периода, дата закрытия, объединение платежей.
   - Формируются связи с задачами, реквизитами, создаются файлы (акт, счёт-фактура и др.).
   - Документ сохраняется в базе, связывается с задачами и файлами.

2. **Просмотр**
   - Доступен через запросы:
     - Администратор: все документы, фильтрация по архиву, оплате, отправке, периоду.
     - Менеджер: только отправленные, относящиеся к его гостинице.

3. **Отправка**
   - Осуществляется мутацией `SendClosingDocuments`.
   - Устанавливается флаг `is_sent`.

4. **Архивация**
   - Мутация `ArchiveClosingDocuments` переводит документы в архив (`is_archive`).
   - Доступна только админу.

5. **Активация**
   - Мутация `ActivateClosingDocuments` возвращает документы из архива.

6. **Оплата**
   - Мутация `MarAsPaidClosingDocuments` устанавливает флаг оплаты (`is_paid`).

7. **Блокировка периода**
   - Мутация `BlockPeriodClosingDocuments` блокирует период для переноса заявок (`is_block`).

---

### Основные поля ClosingDocument

- `admin` — администратор
- `tasks` — связанные заявки
- `files` — файлы документов
- `start_date`, `end_date` — период
- `closing_date` — дата закрытия
- `is_archive`, `is_paid`, `is_sent`, `is_block` — статусы

---

### Результат работы: состав и форматы файлов

#### Какие файлы формируются
- **Акт приёма-передачи** (HTML, PDF) — создаётся с помощью скрипта [`act_creator`](hotels/scripts/act_priem.py).
- **Счёт-фактура** (HTML, PDF) — создаётся с помощью класса [`BillCreator`](hotels/scripts/bill_ver_create.py).
- **Иные документы** (например, для Диадока) — через [`DiadokBuilder`](hotels/scripts/diadok_builder.py) и [`invoice_creator`](hotels/scripts/invoice.py), если требуется.

#### Форматы
- Все документы формируются в HTML, далее преобразуются в PDF (через pdfkit).
- Наименование, номер и сумма указываются в полях модели [`ClosingDocumentFile`](closing_documents/models.py):
  - `name` — наименование (например, "Счёт-фактура")
  - `path` — путь к файлу (относительный или абсолютный)
  - `number` — номер документа (автоматически или вручную)
  - `amount` — сумма в документе

#### Хранение
- Пути к файлам сохраняются в базе в полях `path` (для каждого файла) и `file_path` (для основного файла) модели [`ClosingDocument`](closing_documents/models.py).
- Файлы хранятся на сервере, путь указывается относительно настроек проекта.
- Для каждого документа может быть несколько файлов (ManyToMany).
- Нумерация файлов ведётся по полю `number`.

#### Пример структуры хранения:
- `core/closing_documents/models.py` — описание моделей и полей хранения
- `core/hotels/scripts/act_priem.py` — генерация акта
- `core/hotels/scripts/bill_ver_create.py` — генерация счёт-фактуры

### Запросы и мутации (GraphQL)

- **Мутации**:
  - `adminCreateClosingDocumentByIdHotelAndStartEndDate`
  - `admin_archive_closing_documents`
  - `admin_activate_closing_documents`
  - `admin_send_closing_documents`
  - `admin_mark_as_paid_closing_documents`
  - `admin_block_period_closing_documents_by_id`
- **Запросы**:
  - `admin_get_closing_documents_by_filters`
  - `admin_get_closing_document_by_id`
  - `manager_get_closing_documents_by_filters`
  - `manager_get_closing_document_by_id`

### Диаграмма жизненного цикла (упрощённо)

```
[Создание] -> [Просмотр] -> [Отправка] -> [Архивация/Активация] -> [Оплата] -> [Блокировка периода]
```

---

### Примечания
- Все действия фиксируются через GraphQL API.
- Доступ к операциям ограничен ролями.
- Каждый этап сопровождается изменением флагов и возможностью фильтрации в интерфейсе.
